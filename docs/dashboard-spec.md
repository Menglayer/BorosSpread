# BorosSpread 看板开发口径

依据：2026-10-29 的 `boros-research.md` 与本地 API 证据。用户已明确：以 Boros 双腿价差为主，同时看外部实际资金费率。本文件是下一阶段的产品和验收依据，尚非已实现功能。

## 主视图

默认展示“Boros 价差”：按标的、抵押品、到期日分组，动态发现全部交易所组合。用户输入每腿名义金额，切换做多或做空固定方向的 A−B，查看规模对应的参考成交价和费用。

表格核心列：组合、到期时间、抵押品、两腿动作、mid 价差、bid/ask 价差、指定规模 VWAP、外部浮动费率差、历史平均、Boros 持有成本、两腿深度、同步状态、数据时间。详情中展开两腿和计算过程。移动端用紧凑卡片与详情抽屉承载，不依赖宽表横向滚动完成主要任务。

组合固定 A−B 的顺序，显示“做多 A / 做空 B”或相反动作。排序不能改变组合定义；用户可主动反向。负价差和真实零值完整保留。

## 三类入口

1. 全部 Boros 合成组合：主入口，不受原生挂牌组合数量限制。
2. 原生与合成对比：同一组合同时显示两种结构，比较毛报价、指定规模深度、费用与保证金模型。
3. 外部费率矩阵：覆盖可核实的交易所数据；没有 Boros 对应市场的条目标注“仅观察”。

各入口共享标的筛选和时间范围。期货跨到期日、不同抵押资产的比较可在研究详情展示，不能混进严格匹配组合排名。

## 收益口径

- 默认展示价差和情景现金流，不把单独 Boros 双腿称为固定套利。
- 选择“四腿对冲估算”时，显式加入外部永续两腿及其费用、价格基差与本金占用假设。
- 以一个腿的名义金额 N 为统一名义基数，同时清楚标出双腿总名义敞口是 2N。
- 名义 APR、按全部投入资金算的年化回报、到期利润金额分列。
- 未知费率、缺失费用、缺失深度和未确认单位不按零计算；没有完整成本数据时不显示“净利润”确定值。
- 保证金展示区分模型最低要求与用户情景缓冲。研究阶段不生成账户清算价。
- 不把费用包含进 VWAP 后再次扣减；滑点也只计算一次。

## 数据服务

采用单一服务端行情进程、共享缓存和客户端推送。市场发现与配置低频更新；价差矩阵由共享单腿数据内存计算；深度按当前关注组合订阅和刷新。不要每个浏览器独立向全部交易所抓取。

保存来源 URL、抓取时间、事件时间、sync block、预测/已结算类型、原始单位、归一化结果、覆盖区间。REST 限额按实际 CU 计账，429 退避。断线、缺失、过期、不可开仓、深度不足分别展示，不能继续高亮为机会。

历史价差采用对齐后的市场快照或结算序列。前向填充值携带 stale/observed 标记，不能虚增样本数。历史分位数和 z-score 在可用长度和波动有效时计算，显示窗口及样本覆盖率。

## 第一版边界与验收

第一版提供公开行情的只读研究看板，无需钱包或交易密钥。交易相关按钮先提供官方市场跳转和两腿动作说明。执行模块应在看板和报价口径验收后单独设计。

验收重点：

- 分页不漏市场，自动剔除到期、非正常状态和不合规分组；清楚区分候选与可报价组合。
- 有正、负、零费率、缺腿、不同抵押品、不同到期日、暂停状态和深度不足的计算覆盖。
- 指定规模报价按两腿盘口各自消耗，超出已知深度返回不足。
- 原生与合成对比明确区分毛差、费用和基准期，保留当前实测结算对账样本。
- 实时展示各腿时间；超过阈值或时点不匹配时降级，不显示伪实时。
- 外部源和 Boros oracle 不一致时同时保留来源，不静默替换。
- 桌面、手机宽度以及加载、断网、空数据等状态可用。
- 本地运行、部署连通性与真实交易验证分别记录。
